1. Vue d'Ensemble de l'Architecture

Djassa Online repose sur une architecture découplée de type API-First. Le noyau métier et la
persistance des données sont centralisés sur un serveur backend Laravel communiquant avec une
base de données relationnelle PostgreSQL. Cette API RESTful alimente simultanément l'application
web monopage (React en JavaScript) et les applications mobiles iOS/Android (React Native).


   Principe directeur : Une logique métier unique côté serveur (validation des trocs, séquestre financier
   GeniusPay, génération de codes PIN et gestion des stocks boutiques) garantissant une
   synchronisation temps réel stricte entre les utilisateurs web et mobiles.

3. Architecture Détaillée des Composants

3.1 Clients Frontend : React Web & React Native Mobile

   Application Web (React JS) : Structurée autour de Vite pour un bundling rapide, React Router v6
   pour la navigation et TanStack Query (React Query) pour la mise en cache intelligente des appels
   API et la synchronisation optimiste des offres de troc.

   Application Mobile (React Native) : Utilisation d'Expo / React Native CLI avec navigation native
   (React Navigation), stockage chiffré des jetons d'authentification ( SecureStore ) et compression
   d'images côté client avant upload (format WebP, max 800 Ko) afin d'économiser la bande
   passante mobile.

   Partage de logique : Les schémas de validation (formulaires d'annonces, calcul des soultes de
   troc) et les modèles d'appels API suivent des contrats JSON identiques sur les deux plateformes.


3.2 Backend API & Moteur Métier (Laravel)

   Authentification unifiée : Laravel Sanctum délivre des jetons d'accès Bearer pour React Native et
   gère des sessions SPA sécurisées par cookies HTTP-Only pour le client React Web.

   Moteur de Troc & Paiement Mixte : Service transactionnel dédié ( BarterService ) verrouillant
   temporairement les articles impliqués dans une proposition acceptée afin d'éviter la double vente
   ou le double troc simultané.

   File d'attente asynchrone (Queues) : Traitement en arrière-plan via Redis des tâches lourdes :
   redimensionnement d'images, envoi des notifications Brevo et correspondance automatique avec
   le Mur des Souhaits.

5. Intégration des Services Tiers

5.1 Connexion Automatique via Google Cloud (OAuth 2.0)

L'authentification sociale permet une inscription sans friction sur le Web et le Mobile tout en
garantissant la véracité de l'adresse e-mail :




Djassa Online — Document d'Exigences Techniques (TRD v1.0)                                         Page 3 of 6
1. Configuration Google Cloud Console : Création d'un projet dédié avec écran de consentement
   OAuth et génération de trois identifiants clients distincts (Application Web React, Client Android
   SHA-1, Client iOS Bundle ID).

2. Flux d'authentification : Le client (React ou React Native) récupère un id_token signé par Google
   et le transmet à l'endpoint backend POST /api/v1/auth/google .

3. Vérification côté Laravel : Laravel Socialite / Google API Client vérifie la signature cryptographique
   du jeton auprès des clés publiques Google, crée ou lie le compte utilisateur via google_id et
   retourne le jeton Sanctum de l'application.


5.2 Agrégateur de Paiement et Séquestre (GeniusPay)

GeniusPay gère l'ensemble des flux financiers (achats directs et soultes financières lors des trocs
mixtes) via Mobile Money et cartes :


   Initialisation du paiement : Lorsqu'un acheteur valide une commande ou une soulte de troc
   acceptée, Laravel appelle l'API GeniusPay pour générer une session de paiement sécurisée et
   obtient une référence unique ( geniuspay_ref ).

   Confirmation par Webhook : Un endpoint sécurisé POST /api/v1/webhooks/geniuspay écoute
   les notifications asynchrones. La signature HMAC de l'en-tête HTTP est systématiquement
   vérifiée avant de passer la transaction en statut held (fonds bloqués en séquestre).

   Libération par Code PIN : Une fois les fonds sécurisés, un code PIN à 4 chiffres est généré et
   affiché uniquement chez l'acheteur. Lors de la remise physique de l'article, la saisie de ce code par
   le vendeur déclenche l'appel API de déblocage des fonds vers le portefeuille du vendeur.


5.3 Service de Messagerie et Notifications (Brevo)

Brevo assure la délivrabilité des communications critiques transactionnelles et marketing :


   E-mails Transactionnels (API REST v3) : Envoi automatisé via des templates dynamiques Brevo
   lors de l'inscription, de la réception d'une proposition de troc, de la confirmation de paiement
   GeniusPay et de l'envoi des factures/reçus PDF générés pour les boutiques pro.

   Alertes "Mur des Souhaits" : Lorsqu'un nouvel article correspond aux critères d'un souhait
   enregistré, un job Laravel déclenche un e-mail d'alerte immédiat via Brevo avec lien profond (Deep
   Link) ouvrant directement l'annonce sur React Web ou React Native.

   Vérification SMS (OTP) : Utilisation de l'API SMS transactionnelle de Brevo pour valider les
   numéros de téléphone locaux lors de l'activation d'une Boutique Pro.

7. Sécurité, Performance et Déploiement

7.1 Exigences de Sécurité

   Protection des transactions : Les codes PIN de remise ne sont jamais stockés en clair en base de
   données (hachage Bcrypt ) et expirent automatiquement après 5 tentatives erronées.

   Validation des fichiers : Vérification stricte des types MIME (JPEG, PNG, WebP) et nettoyage des
   métadonnées EXIF lors de l'upload des photos d'articles vers Google Cloud Storage.

   Contrôle d'accès (RBAC) : Utilisation des Laravel Policies pour garantir que seul le propriétaire
   d'une boutique pro vérifiée peut publier des articles avec le statut condition = new et générer
   des factures officielles.
